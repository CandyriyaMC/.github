# Security Policy

## Reporting a vulnerability

**Do not open a public issue or discussion for security vulnerabilities.**

Preferred: use GitHub's **Private Vulnerability Reporting** on the affected repository —
the "Security" tab → "Report a vulnerability". This is enabled organization-wide for new repositories (and can be enabled for older ones on request).

Alternative: email **bejiihiu@icloud.com** with subject line `[SECURITY] <repository>`.

Please include, as far as you can:

- affected repository and version / commit / tag,
- type of vulnerability and its impact,
- reproduction steps or proof of concept,
- any suggested fix if you have one.

## What to expect

- Acknowledgment within ~7 days (best effort — this is a community-run organization).
- We will confirm the report, ask for missing details, and fix on a private branch.
- Public disclosure happens when a fix is released, or after a coordinated deadline (typically 90 days, sooner if you agree).
- We are happy to credit you in the release notes if you'd like.

## Supported versions

Security fixes target the latest release on each repository's default branch. Older versions and forks are supported only if it is explicitly documented in that repository.

## Scope notes

- Minecraft, Velocity, BungeeCord, Arclight, Paper, Forge, Fabric, NeoForge and other upstream projects have their own security policies — report upstream vulnerabilities to their respective projects, not here.
- Issues like "griefing is possible on a public server" are configuration problems, not vulnerabilities — ask in [Discussions](https://github.com/CandyriyaMC/.github/discussions).
